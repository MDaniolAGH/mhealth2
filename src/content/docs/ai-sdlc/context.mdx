<Tldr minutes={5} items={["The agent knows only what is in its context.", "More context means more cost, less focus and more risk.", "Missing facts get filled with confident guesses."]} />

The model knows nothing about your project except what is in its **context window** for the current task: the text it can see at once, measured in **tokens** (pieces of words; an English word is about one to two tokens). Everything the agent works from has to fit there.

<Predict id="ctx-more" question="Modern context windows hold hundreds of thousands of tokens. Why not put the whole repository in, just in case?">

Three reasons. **Cost**: every step of the agent's loop processes the whole context again, and you pay for the tokens. **Focus**: the facts that matter compete with everything else, and old logs pile up. **Risk**: whatever is in the context is sent to the model's provider, secrets and health data included. Try the "Everything, just in case" preset below and watch the meters.

</Predict>

The context of a running agent holds:

- **Rules**: `AGENTS.md` and the task prompt.
- **Project knowledge**: the architecture, decision records, notes and product card it has read (section 3).
- **Code** the agent has opened.
- **Work log**: its own earlier steps and every tool output, such as a long test run.
- **Changes**: the diffs made so far.

Context windows in current models are large: hundreds of thousands of tokens, a million for several models. The size a model advertises and the size it uses well are not the same thing. Filling the window is still a bad idea:

- **Cost.** Every step of the loop processes the context again. Since June 2026 Copilot bills by tokens, in **GitHub AI Credits**, at each model's own rate; other providers bill by tokens too. A long session with a large context costs more on every step. Caching makes repeated context cheaper, not free.
- **Focus.** Irrelevant files and stale tool output compete with what matters. A long session slowly fills with old logs, and the agent can stop following rules that a fresh session follows.
- **Sub-agents help.** A large task can be split so that each part starts with a fresh, small context:

The opposite failure is **missing information**. A model does not stop when it lacks a fact; it fills the gap with something plausible. For the About screen, the most dangerous gap is the client's own words: an agent that has not read `docs/product.md` will write an intended purpose and a contact address, and both will look exactly like real ones.

That is why this pipeline does two things. It gives the agent the facts it needs: the goal, the criteria and, above all, the **project knowledge**. And it demands **evidence**: tests written against your criteria and checks that run without anyone's opinion. A test turns "looks right" into "checked".

:::tip[What to put in the context, and what to leave out]
- **Include**: the criteria, the files the change touches, the relevant project documents, the project rules.
- **Leave out**: the whole repository "just in case", old chat history, unrelated logs.
- **Never include** passwords, API keys, the server's `.env`, or real personal or health data. The context is sent to the model's provider. What the provider may keep, and for how long, depends on your plan: business plans and personal plans have different terms. Know which one you are on.
- **Pick the smallest model that passes your criteria**, and **start a fresh session** when a task is finished, after writing down in `NOTES.md` what the next session needs to know.
:::

<AtWork>On company plans, tokens are real money. Engineers who keep context lean get cheaper, better results, and can explain why.</AtWork>

:::tip[Do this in your project]
In your next task prompt, list the files and documents the agent should read, and nothing else. When the task is done, write in `NOTES.md` one fact the agent had to guess, and add it to the right document. Then start a fresh session for the next task.
:::
