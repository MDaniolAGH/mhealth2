A coding agent can write a Flutter screen in a few minutes. That alone is not a way to build software. Somebody still has to decide what the screen is for, describe it precisely enough to check, give the agent what it needs to know about the project, look at what it did, prove that it works, and be able to explain the change months later.

This guide follows **one feature**, an About screen for the Mood Tracker, from a sketch to a merged pull request. At every stage it shows who does the work, what goes in, what comes out, and what checks it.

## The map

Work flows from top to bottom. The colour of a stage shows who does the work; a stage that spans two lanes is shared. On the left is the **project knowledge**: the documents the agent reads before it plans, and that the documentation stage updates.

**Try it.** Press **Walk through** to follow the About screen through every stage, including a failed check. Use **Show** to add the feedback loops, the knowledge flows or the audit trail. Click a stage, or a document in the project knowledge. The arrow keys step through the walk.

## Where you use this in the course

| When | Which parts | What you do |
|---|---|---|
| **W2** | 1, 2, 4 | how a model works, the cost of context, your pair's `AGENTS.md`, checking an agent's claims about code you took over |
| **W3** | 3, stages 2–4 | the architecture as the agent sees it, checked in the code; the About screen at three levels of specification; an ADR |
| **W4** | stages 5–7, 9 | the agent loop, parallel runs in worktrees, tests that look for bugs instead of confirming; a contribution through a pull request |
| **W5** | stages 6 and 10 | CI with an AI reviewer, MCP, a security policy for agents |
| **W6** | 6 | what working with agents cost: the agent log, commit trailers, the semester's balance |
| **Your pair's brief** | all ten | `ARCHITECTURE.md`, decision records and `NOTES.md` from the first lab; changes through pull requests, gates in CI, reviews by another pair |

:::note[About the worked example]
The About screen is the neutral task from the W3 demo. The client is the fictional rehabilitation clinic from W1, not one of the briefs C01–C07. The artefacts on these pages were **written for this guide** to show what each stage should produce. They are not a recording of a real agent session, and the issue and pull request numbers and the commit hash are invented. Where an artefact contains tool output, it is marked as a placeholder for the real output.
:::
